# BUG: редактирование окружения не управляет коллидирующими пакетными скиллами

> type: bug
> context: audit-code (этап 2), обнаружено при саморевью после коммита ba6c6f2

## Симптом

Если два установленных пакета main-агента содержат скиллы с одинаковым
именом каталога (например, оба `skills/foo`), то в форме редактирования
окружения их невозможно корректно снять/назначить:

1. `freshEdit` предмечает **оба** скилла по одной и той же строке settings
   (`skills/<baseName>`) — пользователь не может отличить их выбор.
2. `updateEnvironment` строит множество выбранных по `baseName(s.path)`
   (у обоих — `foo`), а каталоги назначения считает по `s.name`
   (`foo` и `pkg2/foo` — со слэшем, т.е. вложенный путь). Снятие галочки
   с одного из скиллов не удаляет его каталог из окружения:
   - `createEnvironment` кладёт коллизию в `foo` и `foo-2` (через `uniqueName`),
   - `updateEnvironment` ищет/удаляет `skills/pkg2/foo` — каталог `foo-2`
     остаётся («чужой»), settings.json перечисняет его снова.

## Повторяемость

1. В main-агенте два пакета с пакетным скиллом `foo` (одинаковое имя каталога).
2. Создать окружение с обоими скиллами → каталоги `skills/foo`, `skills/foo-2`.
3. Открыть редактирование (E) — обе строки скиллов отмечены.
4. Снять отметку с любой из строк, сохранить.
5. В окружении оба каталога скиллов остаются; settings.json их перечисляет.

## Причина

Идентичность скилла в форме — по имени (`CreateState.skills: string[]`),
в синхронизации — по `baseName(path)` и `name` одновременно; при коллизии
`baseName` не различает скиллы разных пакетов.

## Предлагаемое решение

Идентифицировать скиллы по пути (`SkillItem.path`) во всех слоях:
`freshEdit` → `updateEnvironment` → settings (`skills/<каталог>` остаётся как
пи-формат, но выбор/удаление — по пути). Альтернатива: запретить выбор
коллизии (мечать только первый) с пометкой в UI.

## Статус

Отложено — редкий кейс (коллидающие имена каталогов скиллов у разных пакетов);
не блокирует текущую работу. Фиксать вместе с полным экраном настроек (этап 3).
