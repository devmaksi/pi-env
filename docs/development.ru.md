# Разработка
[English](development.md) | [Русский](development.ru.md)

**Стек:** Node.js ≥ 22.19 (как у pi 1.3/1.4), TypeScript (ESM, `NodeNext`), ноль runtime-зависимостей.
Dev-зависимости: `typescript`, `tsx`, `@types/node`. Тесты — `node:test`.

## Быстрый старт

```bash
git clone <repo> pi-env
cd pi-env
npm install            # dev-зависимости
npm run build          # компиляция src/ → dist/
npm test               # тесты ядра: tsx --test test/*.test.ts
npx tsx src/index.ts   # запуск TUI без сборки (улучшенная разработка)
npm run start          # запуск собранного CLI (node dist/index.js)
```

## Конвенции

- Вся логика, не требующая TTY, — **чистые функции**, покрытые тестами
  `node:test`; терминальный слой (`terminal.ts`, `run.ts`) остаётся тонким.
- UI-тексты и сообщения — через `t(lang, key)` (`src/i18n.ts`), словари —
  `src/locales/*.json` (ru — базовый, en — полный).
- Документация: файл без суффикса — английский, русский текст — в файлах с
  суффиксом `.ru`; `.en.md` в репозитории нет.
- **Не добавлять** runtime-зависимости без необходимости.
- Изменения раскладки/поведения клавиш — только вместе с обновлением тестов
  `render`/`state` и `AGENTS.md`.

## Отзывчивость

- Долгие внешние команды (`pi install`/`update`/`remove`, `pi mcp add`, `pi mcp list`) уходят в фон:
  экран продолжает отвечать и показывает «⏳ N с». `Esc` на таком экране снимает принадлежащий ему
  процесс; `Ctrl+C` выходит из pi-env, сняв все незавершённые процессы. Таймаут отличим от отмены и
  от обычного провала — `CmdResult.cancelled`, `CmdResult.timedOut`, `CmdResult.timeoutMs` — и в
  статус-строке написано, что именно случилось.
- Время живёт в слое эффектов: `run.ts` держит `opStartedAt` и кладёт в состояние целые секунды как
  `opSeconds`, поэтому `render`/`sections` остаются чистыми. `⏳` входит в `WIDE_CHARS`, иначе
  границы колонок разъезжаются на 2-клеточных терминалах.
- Снимок окружений кэшируется по stat-подписи (`src/env-cache.ts`). Своя мутация — создание/сохранение/
  переименование, корзина, правка MCP, окончание внешней команды, возврат из дочернего `pi` — обязана
  его сбрасывать, иначе список окружений устаревает.

## Съёмка демо-GIF

```bash
pi-env                # сначала закрыть все открытые pi-env — скрипт иначе отказывается
npm run demo          # пересъёмка docs/demo.gif и docs/demo.ru.gif
```

`demo/` — Python 3 стенд (только stdlib): `demo/ptycast.py` ведёт PTY и пишет asciinema
cast, `demo/script.py` — сценарий клавиш и маркеров, `demo/capture.py` закрепляет язык
pi-env и рендерит GIF через `agg` (`demo/bin/agg`, скачивается при первом запуске и в git
не попадает; `demo/out/` тоже). Стенд сам проверяет работу с alt-screen
(`python3 -m demo.capture --selftest`), покрытие — `python3 -m unittest demo.test_ptycast
demo.test_capture`. В `files` package.json `demo/` нет, поэтому в npm-тарбелл он не
попадает.

Подробное описание модели окружений, текущего статуса и дорожной карты — в
`AGENTS.md`.

## Спецификации

Архитектурные решения описаны отдельным документом на каждую фичу — в каталоге
`docs/superpowers/specs/`, планы реализации — в `docs/superpowers/plans/`. Оба каталога
в `.gitignore` (рабочие артефакты разработки): их нет в репозитории, поэтому здесь они
названы текстом, а не ссылкой.

- Корзина окружений — `docs/superpowers/specs/2026-10-24-env-trash-design.md`:
  перенос удалённого окружения в `<root>/.trash` вместо безвозвратного `rm -rf`,
  суб-экран «Корзина» с восстановлением и удалением совсем.

- Основной агент как окружение — `docs/superpowers/specs/2026-11-25-main-pi-as-environment-design.md`:
  окружение определяется путём (`Environment.path`), основной агент — ведущая запись списка
  (`withMain`), его правка пишет `settings.json` точечно и не трогает каталог агента, удаление
  и переименование запрещены, в CLI — `pi-env main`.
- Хранилище каталога моделей — `docs/superpowers/specs/2026-11-25-env-store-models-design.md`:
  общий файл `<root>/.store/models/models.json` (переопределяется настройкой `storeDir` в
  `.pi-env.json` и переменной `PI_ENV_STORE`, у переменной приоритет), `models.json` окружения
  становится симлинком на него, доступность моделей — настройка pi `enabledModels`, своя копия
  каталога уезжает в ветку файловой корзины `<root>/.trash/files/<окружение>--<файл>@<мс>`.
- Общее хранилище пакетов (подрез 2a) — `docs/superpowers/specs/2026-11-26-env-store-artifacts-design.md`:
  каталоги `npm/` и `git/` окружения целиком становятся симлинками на `<root>/.store/npm` и
  `<root>/.store/git`, потому что pi держит пакетные корни внутри каталога агента; общий реестр —
  `<store>/settings.json`, и все `pi install/update/remove` вкладки «Расширения» идут с
  `PI_CODING_AGENT_DIR=<store>`. `scan()` сообщает состояние связи по каждому корню
  (`EnvDetails.rootLinks`), плюс `packageConflicts` (одно имя пакета объявлено разными
  источниками) и `missingPackages` (объявлен, но отсутствует в реестре). Лишняя своя копия
  пакетного корня окружения уходит в снимок хранилища `<store>/<корень>.from-<окружение>@<мс>`,
  а не в файловую корзину: файловая ветка принимает только файлы. При первом включении
  хранилища к общим корням подключается и основной агент.
- Клонирование окружения — `docs/superpowers/specs/2026-11-19-env-clone-design.md`:
  `C` на окружении открывает запрос имени и копирует каталог окружения как есть
  (вместе со своими файлами), а не пересобирает его из каталога main-агента.
