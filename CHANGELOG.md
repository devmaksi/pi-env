## [0.2.2] — не выпущено

### Надёжность

- **Публикация заперта тестами.** Новый реюз-воркфлоу
  `.github/workflows/tests.yml` (`on: workflow_call`): `npm ci` → сборка →
  `npm test` на Node 22 и 24 (`ubuntu-24.04`) — единственное место, где живут
  шаги проверки и список поддерживаемых Node. `ci.yml` (push в `master`/`main`
  и pull request) и `publish.yml` (тег `v*`) теперь только вызывают его, а
  publish-джоб получил `needs: test`: тег → `npm publish` невозможен, пока
  тесты не зелёные. Раньше `publish.yml` тесты не запускал вовсе, а пуш тега
  `ci.yml` не триггерит — наружу мог уйти непроверенный коммит.
- **Согласие `engines`, матрицы и документов** страхует новый тест
  `test/ci.test.ts`: матрица проверки не ниже `engines`, вызовы реюз-воркфлоу
  на месте и своя матрица в вызывающих воркфлоу запрещена, `tests.yml` без
  лишних прав (`contents: read`, без `id-token`), ловушки публикации
  (`--provenance --access public`, `id-token: write`, `npm@11`,
  `ubuntu-24.04`) не потеряны.

### Совместимость

- **Минимальная Node — 22.19.0** (`engines` в `package.json` и
  `package-lock.json`, `README.md` и `README.ru.md`, `docs/installation.md` и
  `docs/installation.ru.md`, `docs/development.md` и `docs/development.ru.md`,
  `AGENTS.md`). Столько же требует сам pi:
  `@earendil-works/pi-coding-agent` 1.3/1.4 — Node `>=22.19.0`; для Node 20 у
  pi отдельная legacy-линия (dist-tag `legacy-node20` → 0.74.2). Матрица CI
  вместо Node 20/22/24 теперь 22 и 24 — активные LTS-линии.

## [0.2.1] — 2026-10-22

### Дистрибуция и документация

- **Попадание в галерею pi.dev/packages**: в `keywords` добавлен `pi-package`
  (по докам pi именно он делает npm-пакет доступным в галерее), а в манифест
  `pi` — `skills` и `image` для превью. Пакет теперь ставится и как pi-пакет:
  `pi install npm:@devmaksi/pi-env`.
- **Скилл `pi-env`**: `pi/skills/pi-env/SKILL.md` — агент умеет создавать
  окружения, запускать их и объяснять раскладку `settings.json`/`mcp.json`.
  Каталог `pi/` добавлен в `files`, скилл едет в npm-тарболе.
- **CI**: `.github/workflows/ci.yml` — сборка и `npm test` на push в `main` и на
  pull request, матрица Node 20/22/24 (раньше в Actions был только publish).
- **README (ru/en)**: бейджи (версия, загрузки npm, CI, лицензия, Node),
  переписан первый экран — питч в одну строку, быстрый старт, раздел «Зачем,
  если есть `PI_CODING_AGENT_DIR`», предупреждение «не путать с
  `@earendil-works/pi-env`», актуализированы вкладки (MCP) и ссылка на CHANGELOG.

### Надёжность

- **Терминал восстанавливается при любом сбое.** Раньше необработанный throw
  (например, доступ к окружению запрещён: `EACCES` при сохранении) или отказ
  фоновой pi-команды оставлял терминал в raw-режиме на alternate screen со
  скрытым курсором — пользователь терял shell. Теперь весь терминальный участок
  цикла под `withShutdown` (`src/shutdown.ts`): вывод терминала выполняется ровно
  один раз при нормальном выходе, исключении, rejection из фоновой команды и по
  `SIGINT`/`SIGTERM`/`SIGHUP`; о сбое сообщает строка `crash.terminal` и stack в
  stderr (код выхода 1). `start()/stop()` терминала идемпотентны, поэтому сбой,
  пока запущен дочерний `pi`, не пишет escape-коды в его экран.
## [0.2.0] — 2026-10-20 (изменения после v0.1.2)

### Новые возможности

- **MCP — вкладка «MCP»**: список серверов main-агента, инфо-панель выбранного,
  «＋ Добавить» (форма на 9 полей stdio/http: имя, тип, команда, аргументы, URL,
  переменные, рабочая директория, описание, exposure) с валидацией, удаление с
  подтверждением (X). Добавление идёт через `pi mcp add`, удаление — чистой
  записью `mcp.json` (последняя запись → удаление файла).
- **MCP в форме окружения**: строка «MCP» в создании и редактировании. В edit —
  union «окружение + main»: копирование серверов main-агента в окружение, удаление
  записей окружения, «Добавить новый»; в create — отметки серверов из main,
  `mcp.json` пишется вместе с окружением.
- **MCP в детализации окружения**: инфо-панель окружения показывает серверы из
  его `mcp.json` (`catalog.mcp` / `details.mcp`).
- **«О программе» — поддержка автора**: строка «Поддержать автора:» и ссылка
  `https://boosty.to/devmaksi` (URL отдельной строкой — виден и в узком режиме).
- Ограничения v1 (осознанно): `headers`/oauth/`timeout` — только в ручном
  `mcp.json`; правка существующего сервера — удалить + добавить; живой статус
  подключения — отложен.

### Исправления

- **readJsonFile не вырезал запятые внутри JSON-строк**: regex trailing-commas
  портил значения вида `{"a":"hello, }world"}` на полностью валидном файле.
  Строковый литерал теперь первая альтернатива — запятые вне строк не трогаются.
- **Коллизии пакетных скиллов портили settings.json при редактировании**: два
  пакета со скиллом одного имени были неотличимы в форме — `freshEdit` предмечал
  оба, `updateEnvironment` удалял по одному имени, снятый скилл оставался
  каталогом и снова попадал в settings.json. Идентичность скилла — имя каталога
  окружения (`envSkillDirName`: `pkg-b/dup` → `pkg-b-dup`) в create, update и
  freshEdit; `listSkills` выдаёт уникальные имена (`uniqueName`).
  Ограничение: legacy-каталоги вида `foo-2` в существующих окружениях не мигрируют.
- **Версия в «О программе»** больше не хардкод (`pi-env 0.1.0`): берётся из
  `package.json`.

### Рефакторинг

- Ужимки по итогам аудита (~−54 строки): общий `readJsonFile` вместо трёх копий,
  `listEntries` вместо `listFiles`/`listDirs`, общий `busySection` вместо
  `createBusy`/`extBusy`/`mcpTabBusy`, `basename`/`dirname`/`osHomedir` из
  стандартных модулей вместо самописных, единый `TEXT_ROWS`, `isPrintable`.
- `render.ts` разбит на секции (`renderCreate`, `renderExtTab`, `renderEnvList`,
  `renderSettings`, `renderAbout`, `renderFooter`); `render()` — только диспетчер.
